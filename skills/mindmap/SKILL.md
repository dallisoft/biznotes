# 마인드맵 만들기

노트북 컨텍스트를 읽고, 주제 `params.topic`을 루트로 하는 **마인드맵 트리 JSON 한 개**를 만든다.
컨텍스트는 두 부분이다. `<source_digests>`는 고른 소스 모두의 요약이고 번호가 없다.
`<source_excerpts>`는 소스마다 뽑은 발췌이고 앞에 `[n]` 번호가 붙는다.
추가 지시사항 `params.extra`가 있으면 따르되 아래 출력 규칙과 문서 형태는 바꾸지 않는다.

## 출력 규칙 (반드시 지킨다)

1. **JSON 객체 하나만** 출력한다. 앞뒤 설명 문장, 마크다운, 코드 펜스(백틱 세 개)를 쓰지 않는다.
2. 깊이는 루트를 포함해 **최대 3단계**다(루트 → 가지 → 잎).
3. 노드는 모두 합쳐 **60개 이하**를 권장한다. 상한(200개)을 넘으면 뷰어가 아래 단계부터 잘라 낸다.
4. `label`은 **40자 이하**의 명사구로 쓴다. 문장·번호·이모지를 넣지 않는다.
5. `id`는 트리 안에서 **서로 다르게** 짓는다(예: `root`, `n1`, `n1-1`). 빈 문자열을 쓰지 않는다.
6. 소스에 없는 내용을 지어내지 않는다. 근거가 약한 가지는 만들지 않는다.

## 문서 형태

- 최상위 객체: `version`(정수 1), `root`(노드)
- 노드: `id`(문자열, 필수), `label`(문자열, 필수), `children`(노드 배열, 잎이면 빈 배열 또는 생략)
- 선택 필드 `cite`: 그 노드의 근거가 된 발췌 번호 `[n]`의 정수 배열(예: `[1, 3]`). `<source_excerpts>` 발췌 앞의
  번호를 그대로 쓴다. 요약에는 번호가 없으므로 요약만 근거인 노드는 `cite`를 생략한다.
  근거가 없는 상위 분류 노드는 `cite`를 생략한다. 소스 ID나 다른 식별자는 쓰지 않는다.

예시(형태만 참고 — 내용은 소스에 맞게 새로 쓴다):

    {"version": 1, "root": {"id": "root", "label": "커피 추출", "children": [
      {"id": "n1", "label": "에스프레소", "cite": [1], "children": [
        {"id": "n1-1", "label": "9기압 압력", "cite": [1], "children": []}
      ]},
      {"id": "n2", "label": "핸드 드립", "cite": [2, 3], "children": []}
    ]}}

## 작성 순서

1. `<source_digests>`로 모든 소스를 훑어 `params.topic`에 맞는 핵심 주제 3~7개를 고른다 — 이것이 1단계 가지다.
   일부 소스에 치우치지 말고 소스 전체를 덮게 고른다.
2. 가지마다 요약과 발췌가 뒷받침하는 하위 개념을 2~6개 붙인다 — 이것이 2단계 잎이다.
3. 노드마다 근거 발췌 번호를 `cite`에 넣는다.
4. 출력 규칙 1~6을 다시 확인하고 JSON만 낸다.
